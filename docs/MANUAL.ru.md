# ai-starter — мануал простыми словами

## Что это такое, в двух словах

Представь, что Claude — мастер, который каждое утро приходит на стройку **с полной потерей памяти**.
ai-starter — это **тетрадь прораба**, которая лежит прямо на стройке:
- на первой странице — **что строим** (цель);
- дальше — **где остановились вчера** и **что делать сегодня**;
- отдельная полка — **справочник** со всем, что узнали по ходу.

Мастер приходит, первым делом читает тетрадь — и работает дальше, как будто ничего не забывал.
Тетрадь — это папка `ai/` в твоём проекте. Читает её Claude сам, тебе ничего вставлять не нужно.

---

## Шаг 1. Что должно быть на компьютере

Открой терминал и проверь, что всё есть:

```bash
claude --version
git --version
python3 --version
```
Если в ответ пришла цифра версии — есть. Если `command not found` — программы нет, её надо поставить.
python нужен только для одного случая (см. шаг 4), без него тоже можно.

На Windows всё делается в **Git Bash** — это терминал, который ставится вместе с Git для Windows.

---

## Шаг 2. Скачать ai-starter (один раз на компьютер)

```bash
git clone https://github.com/swittchen/ai-starter.git ~/tools/ai-starter
```
Это скачает шаблон в папку `tools` в твоей домашней папке. Значок `~` = твоя домашняя папка.
Хочешь другое место — пиши свой путь, например `/data/имя/tools/ai-starter`.

---

## Шаг 3. Сделать короткую команду (один раз)

Чтобы не писать каждый раз длинный путь, заводим **alias** — это как ярлык на рабочем столе, только для терминала:

```bash
echo "alias ai-starter='bash ~/tools/ai-starter/install.sh'" >> ~/.bashrc
source ~/.bashrc
```
- Первая строка дописывает ярлык в файл `~/.bashrc` — это файл, который терминал читает при каждом открытии.
- Вторая — чтобы ярлык заработал прямо сейчас, без перезапуска терминала.

Если в шаге 2 ты положил шаблон в другое место — поменяй путь в первой строке.
Проверка: `ai-starter --help` должен показать подсказку.

## Шаг 4. Поставить в проект

**Новый проект:**
```bash
ai-starter ~/projects/moj-projekt --lang ru
cd ~/projects/moj-projekt
git init
```

**Уже существующий проект (например, твой код):**
```bash
cd ~/projects/lims-integration
ai-starter . --lang ru
```
Точка `.` значит «вот эта папка, где я сейчас».

Не бойся за свои файлы — установщик **ничего не затирает**:
- твой `CLAUDE.md` останется, в конец допишутся 4 строки;
- твои настройки `.claude/settings.json` останутся, наши к ним добавятся (а старая копия сохранится как `settings.json.bak` — вот тут и нужен python);
- код не трогается вообще.

В проекте появится папка `ai/` (тетрадь) и папка `.claude/` (механика).

### Где эта папка `.claude` и почему её не видно
Она лежит **прямо в папке проекта**. Её не видно, потому что имя начинается с точки — так в Linux и macOS помечают «скрытые» файлы.
- Посмотреть в терминале: `ls -a`
- В файловом менеджере Linux: `Ctrl + H`; в macOS Finder: `Cmd + Shift + .`; в Windows: «Вид» → «Скрытые элементы».

**Руками туда ничего класть не надо.** Есть ещё вторая, «личная» `.claude` у тебя в домашней папке (`~/.claude`) — это общие настройки Claude Code, её тоже не трогаем.

## Шаг 5. Первый запуск

1. В папке проекта набери `claude`.
2. Claude Code спросит, **доверяешь ли ты этой папке**. Ответь **да**. Это важно: без этого он пропускает часть настроек.
3. Набери `/kickoff`. Claude начнёт **интервью** — по одному вопросу:
   - что должно получиться в конце;
   - зачем и для кого;
   - **как проверить, что готово** — и тут он будет настаивать на конкретике.
     Плохо: «удобный сервис». Хорошо: «команда `./mvnw test` проходит без ошибок».
   - чего мы сознательно **не** делаем;
   - сроки и ограничения.

   Если это уже существующий код, Claude перед интервью сам осмотрит проект и составит «карту» (`ai/MAP.md`).
4. В конце Claude сделает черновик цели `ai/GOAL.draft.md`. Открой, прочитай, поправь, если надо, и **заморозь**:
   ```bash
   mv ai/GOAL.draft.md ai/GOAL.md
   chmod a-w ai/GOAL.md
   ```
   `mv` — переименовать черновик в настоящую цель. `chmod a-w` — запретить запись в файл, чтобы цель случайно не поменялась.
5. Сделай первый коммит. Текст Claude предложит:
   ```bash
   git add -A
   git commit -m "текст, который предложил Claude"
   ```

## Шаг 6. Как работать каждый день

Ритм очень простой — **одна задача за раз**:

| Что делаешь | Что происходит |
|---|---|
| `claude` | Claude сам читает тетрадь и пишет: цель / где мы / что дальше |
| работаешь над **одной** задачей | Claude берёт её из плана `ai/PLAN.md` |
| `/save` | Claude записывает в тетрадь всё важное и предлагает текст коммита |
| `git add -A && git commit -m "…"` | сохраняешь версию — это делаешь **ты** |
| `/clear` | Claude очищает разговор. Не страшно — всё уже в тетради |

**Почему одна задача и `/clear`?** Каждое твоё сообщение Claude отправляет вместе со *всем* предыдущим разговором. Чем длиннее разговор, тем дороже каждый шаг и тем быстрее кончается лимит. Короткие сессии = дёшево.

**Забыл сделать `/save`?** Ничего. Если работа не сохранена 40 минут, Claude сам остановится и сохранит. Если сессия оборвалась (свет выключили) — при следующем запуске он скажет «прошлая сессия оборвалась» и первым делом сохранит.

## Команды

| Команда | Что делает | Когда |
|---|---|---|
| `/kickoff` | интервью и план | один раз, в начале |
| `/save` | записать всё в тетрадь | после каждой задачи и в конце |
| `/breakdown` | разбить большой кусок на маленькие задачи | когда задача слишком большая |
| `/check` | проверить, выполнена ли цель | когда кажется, что готово |
| `/ingest ai/raw/файл` | прочитать документ и разложить знания в справочник | когда добавил статью, спецификацию, заметки |
| `/query вопрос` | ответить по справочнику | когда нужно вспомнить, что уже знаем |
| `/lint` | уборка в справочнике | раз в неделю |
| `/drift` | проверка «не ушли ли мы в сторону» | раз в несколько сессий |
| `/context` | сколько памяти разговора уже занято | когда интересно |
| `/clear` | очистить разговор | после `/save` |

## Что лежит в тетради (папка `ai/`)

| Файл | Что это простыми словами |
|---|---|
| `GOAL.md` | **Что строим.** Меняешь только ты |
| `STATE.md` | **Где остановились** и что делать дальше |
| `PLAN.md` | **План:** большие этапы и маленькие задачи |
| `MAP.md` | **Карта:** какие есть части программы или главы книги |
| `DECISIONS.md` | **Журнал решений:** что выбрали и почему — чтобы не спорить заново |
| `LOG.md` | **Дневник:** по 3–5 строк о каждой сессии |
| `BACKLOG.md` | **Ящик идей «потом»** — чтобы не отвлекаться сейчас |
| `wiki/` | **Справочник:** всё, что узнали. `wiki/index.md` — его оглавление |
| `raw/` | **Исходники:** документы, которые ты принёс. Claude их только читает |
| `sessions/` | страховочные копии разговоров. В git не попадают, можно удалять |
| `RULES.md` | правила для Claude — как вести себя в этом проекте |

Claude каждый раз читает только **цель, состояние и план** — это коротко. Всё остальное он открывает, только когда нужно, и только нужный кусок. Поэтому стоимость старта почти не растёт, даже если проект огромный.

## Для программистов

- В карте `ai/MAP.md` — модули и пакеты, а не каждый файл.
- Команды сборки и тестов допиши в корневой `CLAUDE.md` (ниже блока ai-starter). `/kickoff` предложит это сам.
- «Как проверить, что готово» — это тесты. Задача готова, когда её тест зелёный.
- Правила для одного модуля можно положить в `CLAUDE.md` прямо в папке модуля — Claude прочитает его, только когда работает там.
- Подводные камни вроде «этот сервис отдаёт даты без часового пояса» — в `ai/wiki/`, чтобы не наступать на них каждую сессию.

## Для книги

- Главы — в папке `book/` (`ch01.md`, `ch02.md` …), в карте — по 1–3 строки на главу.
- `ai/wiki/` — «библия книги»: герои, места, хронология, правила мира. Claude не перечитывает все главы — он открывает нужную страницу справочника.

---

## Что Claude делать нельзя (и это проверено)

- Менять цель `ai/GOAL.md` — ни редактором, ни хитрыми командами вроде `mv`, `cp`, `echo >>`.
- Менять исходники в `ai/raw/`.
- Делать `git add`, `git commit`, `git push`, `git reset`, `git checkout`.

Всё остальное — можно: писать код, запускать тесты, смотреть `git status` и `git diff`.

## Если что-то не так

| Что случилось | Что делать |
|---|---|
| Claude ничего не «вспоминает» при старте | Запусти `claude` в **корне** проекта и ответь «да» на вопрос о доверии |
| Хуки молчат | `chmod +x .claude/hooks/*.sh` — это делает скрипты «запускаемыми» |
| Claude ругается на строку в `settings.json` | удали эту строку — её могли переименовать в новой версии Claude Code |
| Слишком часто просит `/save` | открой `.claude/hooks/stop-check.sh` и увеличь `MINUTES=40` и `MAXFILES=15` |
| Хочу поменять цель | `chmod u+w ai/GOAL.md` → поправь → `chmod a-w ai/GOAL.md` |
| Вышла новая версия ai-starter | `cd ~/tools/ai-starter && git pull`, потом в проекте `ai-starter . --update` (тетрадь не тронется) |
| Claude читает много файлов подряд | останови и скажи: «через MAP.md и поиск, не читай всё» |
| Разговор стал медленным | `/save` → коммит → `/clear` |
