**Шаг 0 — что за проект.** Посмотри корень проекта (`ls`, без чтения файлов).
- Если здесь уже есть код (pom.xml, build.gradle, package.json, src/ …): запусти субагента Explore с заданием «составь обзор кодовой базы: модули/пакеты, назначение каждого в 1–2 строки, как собрать и запустить тесты, ≤ 60 строк». Из его ответа заполни ai/MAP.md. Сам файлы кода не читай.
- Если проект новый — пропусти.

**Шаг 1 — интервью**, по ОДНОМУ вопросу за раз:
1. Цель одной фразой — что должно существовать в конце, чего сейчас нет.
2. Зачем и для кого.
3. 3–5 критериев готовности. Для каждого добейся способа проверки: команда (сборка, тест), файл или действие, по которому любой убедится, что критерий выполнен. Размытое («удобно», «хорошо») не принимай.
4. Не-цели — что сознательно не делаем.
5. Ограничения: срок, технологии, бюджет.

**Шаг 2 — файлы:**
- Результат интервью → ai/GOAL.draft.md в формате ai/GOAL.md, но БЕЗ первой строки-маркера `project-memory:unset` (сам ai/GOAL.md менять тебе запрещено).
- ai/PLAN.md: 3–7 вех, каждая закрывает критерий K; первую веху сразу разбей на задачи (правила — в навыке /breakdown).
- ai/MAP.md: структура будущего результата, если ещё не заполнена.
- ai/LOG.md: запись «сессия 1 — kickoff».
- ai/STATE.md (последним): веха M1, задача T1, следующий шаг.
- В корневом CLAUDE.md замени `<НАЗВАНИЕ ПРОЕКТА>`; для кода допиши ниже маркеров команды сборки и тестов.
